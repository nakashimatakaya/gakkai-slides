# 学会スライド規約 正典

唯一の正本。スライドを作る・直す前に毎回読み、出力後に `scripts/check_deck.py` で機械検査する。gozen3ji/consulting-pptx-skill（MIT）の約80項目の規約から学会発表に効くものを選び、学会向けの規則（ガレメン、ドキュメントプラス、麻酔科学会COI規定）と、ぼくの設計条件（赤黒、Noto Sans JP、box禁止、箇条書き、ページ番号）を重ねた。レビューで受けた指摘は末尾の「追記」に1行ずつ足して育てる。AIはセッションごとに忘れるので、口頭で注意しても定着しない。ファイルに書いて毎回読ませるのが唯一の方法。

## 0. 着手前（型から入らない）
1. ストーリーラインを先に作る。各スライドで伝えることを1行ずつ並べ（これが将来のタイトル列または主張列になる）、ユーザーと合意してから枚数と型を決める。
2. 数値・日付・固有名詞は一次ソース（解析結果、抄録、論文）と照合する。「見つからない」と「存在しない」を区別し、未提供は（要記入）のまま渡す。
3. 出力後は check_deck.py の重大0を確認し、タイトルと主張の一覧（`--story`）を通し読みしてストーリーが繋がるか人が確かめる。
4. 良いスライドは型ではなく流し込んだ後の調整で決まる。表を2枚に割る、主張行を帰結形に書き直す、タイトルの通し読みで繋ぎ直す。指摘は本ファイルに追記する。

## 1. タイトルと主張
1. 学会の既定は「話題タイトル＋下部の主張1行」。短い口演や研究室内発表では「メッセージタイトル」（結論をタイトルに書き、主張行を省く）でもよい。1デッキ内で混ぜない。
2. タイトルは1行・全角40字以内。体言止め。「〜です」「〜ます」で終えない。色分けしない。「Step1」「①」を文字連結してタグ代わりにしない。
3. 主張行・メッセージタイトルは主語と述語が分かる普通の文で書く。長い連体修飾で名詞に畳み込まない。数だけを軸にしない（「3つの知見」でなく中身を書く）。
4. タイトルだけを上から順に読んで1本のストーリーになること。同じ文型が6割以上並んだら、主張ではなくテンプレを写している疑い。
5. タイトル直下の説明行・導入文を置かない。図表の直上のラベル行、画像下のキャプションも置かない。例外は「軸タイトル」1行（何のデータか＋単位・期間。例「30日死亡率、%、2018〜2024年」）。

## 2. レイアウト
1. 1スライド＝1メッセージ＝1テーマ。2テーマあれば2枚に割る。論点が多い1枚は、同じ版面に要素を足していく段階ビルドアップで2〜3枚に割る。
2. 上下に読ませない。関係しない内容の縦積みは禁止。分けるなら左右（各側に見出し）。図があるスライドは、図が主役なら図を左・コメントを右、箇条書きが主役なら文を左・図を右。デッキ内で統一する。
3. 左右カラムの下端と見出しの上端を揃える。片側だけ短く空く形は不可。
4. 1スライドに表は1つ。表の下にカードや別内容を積まない。
5. 囲みボックス（塗り・角丸・カード）は使わない。本文は地のテキスト。下部の結論帯（GOAL/POINTのbox）も作らない。主張行はプレーンな太字テキスト1行。
6. 宙に浮いたラベル・チップ・小要素を置かない。必ず表・図・箇条書きの構造の中に入れる。
7. 限界・懸念を出すスライドには対処（感度分析、比較可能性の確認、次の研究）をセットで付ける。限界の列挙だけで終えない。
8. 扱う範囲を絞ったことは、絞った図の上で言う。全体集団のフロー図の中で解析対象だけを示し「本解析の対象」と注記する。
9. 番号・記号は後続で参照するときだけ導入する。参照しない丸数字や「柱1／柱2」は付けない。
10. 内容が少なく下部に余白が出るスライドは垂直中央揃え。図が大きいページは上詰め。

## 3. 色・罫線・図
1. 色は黒・赤・グレー。赤は強調にだけ、1枚2箇所まで。色に意味を持たせるなら同一スライドに凡例。見た目だけのダーク塗りは禁止。
2. 角丸禁止。塗りのある要素に枠線を付けない。罫線は「その先に区切る対象がある場所」にだけ引く。最終行の下、スライド最下部、タイトル下には引かない。
3. カテゴリの色分けにはグレーを含める。基準・対照群はグレー、立てたい群だけ赤。
4. 上限が定義された指標（割合、達成率、AUROC、相関係数）は軸を0〜最大のフルスケールで描く。必要なら参照線を添える。
5. 自施設の数値には測定条件（対象、n、期間、定義）を注記する。
6. 比較表のハイライトは優れている側に付ける。自分の手法の列だけ常に色付きにしない。競合比較には相手が勝つ軸も入れる。

## 4. 表
1. 表ヘッダーは本文より大きく太字。ヘッダー行の薄グレー塗りは可。
2. セルに2文以上の長文を流し込まない。2文以上なら箇条書きに分解する。
3. 行＝項目軸、列＝観点軸。左端の軸は意味のある粒度で束ねる。左右2つの箱を見比べさせるより、行＝観点・列＝比較対象の表にする。

## 5. 文章・ラベル
1. 丸括弧（）を多用しない。補足は文か「／」で。
2. 勝手な短縮・造語をしない。略語は初出でフル表記に併記してから使う（「target trial emulation（TTE）」）。内輪の造語は使わない。
3. 箇条書きは1項目2行以内、階層2段まで。同じ階層内で語尾を揃える（体言止めなら全部体言止め）。ですます調は使わない。
4. 1資料1用語。同じ概念に複数の表記を使わない（患者/症例、死亡率/死亡割合、ノルアドレナリン/ノルエピネフリン、メモリ/メモリー）。作成後に表記ゆれを見る。
5. 「ラベル：説明」「ラベル — 説明」の連結が箇条書きで繰り返されるなら、構造の設計不足。表にして列を分ける。
6. AI臭の語（まさに、非常に、極めて、ソリューション、シームレス、定型締め、三点セット構文、絵文字）を除去する。deslop-ja の check.py をスライド原稿にもかける。
7. 比喩的・転用的な語には「」を付け、資料内で定義する。

## 6. 出力前の機械チェック（check_deck.py が見るもの）
- 比率が指定どおり（16:9 または 4:3）
- プレースホルダー（Text N、ラベルN、タイトルN、YYYY、Source N、◯◯、（要記入））が残っていない → 残っていたら重大
- タイトルが「です／ます」で終わらない、40字以内、空でない
- タイトルの同じ文型が6割以上並んでいない
- 角丸・塗りbox・パレット外の色・アクセント線がない
- Noto Sans JP、本文16pt以上、出典12〜14pt
- ページ番号が連番（タイトル以外）
- 版面からのはみ出し、ページ番号との重なりがない
- 表記ゆれ（全角半角数字の混在、句読点スタイルの混在、長音の有無）
- `--story` でタイトルと主張の一覧を出し、人が通し読みする

## 7. 取り込まなかったもの
consulting-pptx-skill の36型SlideSpec、27パーツ集、シェブロン、ハーベイボール、タグチップ、裏表紙ロゴ、Node パイプラインは、学会スライドでは装飾過多になるので使わない。必要になったら元リポジトリを直接使う。
